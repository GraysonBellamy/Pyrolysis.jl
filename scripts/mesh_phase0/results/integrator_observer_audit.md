# FBDF observer audit on the performance-audit decks

Generated by `scripts/mesh_phase0/baselines/integrator_observer_audit.jl`; data in `integrator_observer_audit.csv`; log alongside. Run as `julia --project=test --startup-file=no --threads=1 <script>` from the repository root.

Why: the audit's integrator ranking (`newton_baseline.md`, table (b), from the gitignored `docs/performance_audit/solves.csv`) ran every integrator with the package's step-update callback, which flags a derivative discontinuity after every accepted step; a multistep method restarts at order one on every such flag, so the audit's FBDF rows were suspected of measuring a crippled configuration. Here the step-update callback is replaced in-process (same technique as `integrator_flag.jl`): `current` = mirror + `derivative_discontinuity!(integrator, true)` (the package), `observer` = mirror + `derivative_discontinuity!(integrator, false)`. Decks: `problem_for(kind, n)` copied from `scripts/performance_audit/audit.jl` (eulerian and ale: PMMA, surface absorption; ale_darcy: wood with Darcy flow and Beer–Lambert) at 25 and 100 cells, 80 s, 3 outputs, the deck's own solve kwargs; Jacobian strategy and linear solver are the package defaults (Eulerian: `Structured(strategy = DirectSolve())` + KLU; ALE: `Structured(strategy = ApproxSolve())` + KLU), every integrator passed as a constructor so `_resolve_integrator` attaches that linear solver and `autodiff = AutoFiniteDiff()` (unused: the package supplies `jac!`). `KenCarp4_raw` = `KenCarp4(smooth_est = false)`. Tolerances abstol 1.0e-8, reltol 1.0e-6 (the `solve` defaults, as in the audit). Reference per deck: KenCarp4 with the flag set at abstol 1.0e-10, reltol 1.0e-8 (the audit's convention; one solve); a second tight solve with FBDF as an observer at the same tolerances bounds the reference's own error (`cross-check`, the final-time difference between the two; candidate errors below it are not resolved). `err T final` = maximum absolute temperature difference over cells at t = 80 s against the reference; `err T all` = the same over the three outputs; `err z final` = maximum node-position difference at the final time (ALE only). Warm time = median of 3 solves after one warm-up; `maxiters = 200000`, wall-clock guard 300.0 s per solve. Wall times are indicative (shared machine, another Julia process running concurrently).

With the flag set FBDF does not finish any deck here (`MaxIters` at 200000 steps, one Jacobian, one Newton iteration per step, reaching only t = 3–7 s of 80 s), so the audit's FBDF rows cannot have run under an effective per-step restart: they correspond to the observer configuration. `newton_baseline.md` reports FBDF at mean rank 1.17 by time (first on 5 of 6 decks) and 2.17 by error.
